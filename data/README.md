# Sample data

`sample/tickets.csv` is **fully synthetic**. It is generated by
[`generate_sample_data.py`](generate_sample_data.py) with a fixed seed (42), so
running the script again produces an identical file (CI checks this).

* Fictional company: *Northwind Broadband*, a UK home-broadband provider.
* 1,981 tickets across 26 weeks (March to August 2026), 6 categories and 14 underlying issues.
* Customer IDs and emails are random and use the reserved `example.com` domain.
* About 7% of `agent_tag` values are deliberately wrong, to mimic noisy historical tags.
* An emerging issue (`app_crash_v52`) is injected into the final 14 days.

`true_category` and `true_issue` are ground-truth columns used only by
`scripts/evaluate.py`. The application ignores them, and a real helpdesk export
would not contain them.

## Using your own data

Export tickets as CSV with at least `ticket_id`, `created_at` and `body`.
Optional columns: `subject`, `channel`, `customer_id`, `customer_email`,
`customer_tier` (standard / premium / business) and `agent_tag`. Remove or
pseudonymise personal data before importing outside a production environment.

`example_upload.csv` is a small file in a different format (other column names, day/month/year dates, one bad date and one missing message) for trying the guided import wizard.
